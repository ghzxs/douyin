# 调研报告.md 模板（九段结构）

先读取 `report_data.json` 的 `quality`。顶部信息块必须写：抖音号、粉丝、获赞、IP、采集日期、主页作品数、实际采集数、覆盖率、`capture_status`、样本时间跨度。

紧跟数据口径：点赞/评论/转发/收藏/发布时间为网页公开字段；缺失保持未知；单作品播放不可得；只有 `capture_status=complete` 才可称完整采集，`partial` 只能称已采集样本。

## 一、账号速览

表格：公开简介 / 公开体量 / 样本更新强度 / 已观察到的内容定位 / 证据来源。用一句带限定词的账号画像收束；定位和变现属于推断。

## 二、数据盘点

- 写样本点赞合计、均值、中位、最高；评论/转发/收藏只统计已知值。
- 写高赞分布：100万+ / 10–100万 / 1–10万 / 1万以下的条数和样本占比。
- 判断样本是否由少数高赞内容驱动，不外推到未采集作品。

## 三、样本高赞内容（Top 8）

表格：赞 / 评论 / 转发 / 收藏 / 合集或系列 / 日期 / 标题 / 原视频链接。标题模式、时长和收藏绝对量可做观察；没有播放量时不计算收藏率或互动率。

## 四、合集战绩

表格：合集名 / 公开播放量 / 集数 / 样本内相关作品数与均赞。`play_vv` 缺失显示 `—`。区分合集公开播放与单作品点赞，不能混算。

## 五、选题矩阵

优先使用真实 `mix_name`。若 agent 根据标题另行归类，先写清分类规则，再列系列 / 样本条数 / 样本均赞 / 代表作；不要把临时分类写成账号官方栏目。

## 六、人设与表达风格

分“已观察事实”和“推断”两段。仅凭简介/标题/封面时明确证据有限；实际打开视频后才描述镜头、口播、剧情和表演。未采集评论正文时不写热评情感。

## 七、变现路径（推断）

表格：候选路径 / 可见信号 / 反证或缺口 / 置信度。简介中的商务、橱窗、直播或私域信号可引用；没有交易数据时不判断收入和转化效果。

## 八、可复制清单 →〈用户赛道 / IP〉

写 6–10 条可落地动作。每条包括：动作、来自哪个样本证据、如何迁移、要验证的指标。用户未指定赛道时给通用清单，并标注需二次适配。

## 九、风险与不可照搬项

写赛道差异、合规边界、样本完整性、数据盲区、真人 IP 不可复制性，以及下一轮最低成本验证动作。

结尾固定标注：数据来源（抖音网页公开接口）｜实际采集 N 条 / 主页展示 M 条｜capture.status｜分析：agent。
